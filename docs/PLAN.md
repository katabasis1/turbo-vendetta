# PLAN.md — план разработки «Турбовендетта» / Turbo Vendetta

> Нумерация: Этап N → подэтап N.M. Чекбокс ставится только после чекпоинта (см. AGENTS.md).
> Размер подэтапа: S — одна короткая сессия, M — 1–2 сессии, L — 3+ сессии. Это оценка, а не обещание.
> Каждый закрытый этап = версия. Начиная с v0.0.1 каждая версия уходит в GitHub.

## Бюджеты (стартовые значения — проверяем на v0.0.1)
| Параметр | Старт | Как проверить | Если не проходит |
|---|---|---|---|
| FPS ПК / средний Android | 60 / ≥ 30 | Яндекс Браузер, 8 машин на трассе, монитор `Performance` | меньше draw calls, частиц, без динамических теней |
| Draw calls (моб.) | ≤ 100 | `RENDER_TOTAL_DRAW_CALLS_IN_FRAME` | атласы, MultiMesh, объединение мешей |
| Треугольники в кадре | ≤ 150k | монитор рендера | LOD, проще декор |
| Машина | ≤ 4k треугольников | отчёт MeshForge | упрощение сечений |
| Тени | блоб-тени под машинами | визуально | — |
| Размер сборки | ≤ 60 МБ распакованно (лимит 100) | размер папки экспорта | сжатие, облегчённый шаблон |
| Загрузка до игры | ≤ 8 с на 4G | throttling в DevTools | ленивые ресурсы, меньше стартовая сцена |
| Заезд | 90 с | ≥ 3 заездов за сессию, ≥ 80% новичков доезжают | короче трасса, проще первые повороты |
| Запись призрака | 10 Гц, ≤ 150 КБ | размер JSON | 5 Гц + сплайн |

## Риски
1. В Computer нет Godot → проверка у пользователя, пока не решён D-004. Митигация: валидатор, мелкие шаги, чек-листы в логе.
2. Ошибки в рукописных `.tscn` → `tools/validate.py` + минимальные итерации.
3. Производительность мобильного веба → тест на телефоне с v0.0.1.
4. «Красиво» при офлайн-моделинге → сильный арт-дирекшн, стилизация шейдерами, концепт-арт до ассетов.
5. Качество музыки → синтез + вариант CC0-треков от пользователя.
6. Мало записей для призраков на старте → боты + «призраки разработчика».
7. Трактовка п. 1.10.4 (одна рука) → вопрос в поддержку Яндекса до этапа 3.
