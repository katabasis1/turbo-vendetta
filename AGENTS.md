## Проект
3D аркадная гонка с автобоями для Яндекс Игр.
- Движок: **Godot 4.7.2**, рендерер **Compatibility (WebGL 2)**, язык **GDScript** (C# в веб не экспортируется).
- Название: **«Турбовендетта: гонки на выбывание» / "Turbo Vendetta: Knockout Racing"** (D-007). Slug для файлов и репозитория — `turbo-vendetta`. Старое рабочее имя NEON RIVALS не использовать.
- Концепция: `docs/CONCEPT.md`. Архитектура: `docs/ARCHITECTURE.md`. План: `docs/PLAN.md`. Лог: `docs/PROGRESS.md`. Решения: `docs/DECISIONS.md`.
- Визуальный стиль: **«Аниме-аутран 90-х» / «Закатная трасса»** (D-006, D-012) — синтвейвовский закат на японских эстакадах, cel-shading без обводки, при таране — комиксовая вспышка и линии скорости. Правила — `docs/STYLE_GUIDE.md` (v1 утверждён, D-013; правки — только новой версией гайда + D-xxx), кадры — `docs/art/style_frames/`. Отклонено навсегда: «Поп-день» (B), «Неон-поп», классический набор «сетка + полосатое солнце + пальмы».
- Игру, модели, трассы, шейдеры, звук делает агент. Пользователь — продюсер и тестировщик.

## Ритуал начала сессии (обязательно)
1. Прочитай этот файл целиком.
2. `docs/PROGRESS.md` → блок **«ТЕКУЩАЯ ПОЗИЦИЯ»**: версия, этап, подэтап, следующий шаг.
3. `docs/PLAN.md` → найди подэтап, прочитай критерии готовности (DoD).
4. `docs/DECISIONS.md` — принятые решения молча не меняются. Хочешь изменить — новая запись D-xxx.
5. Восстанови рабочую копию в `/tmp/work` (mount `/files/pod` медленный, работаем локально):
   - до перехода на GitHub: `bash /files/pod/project/tools/agent/restore.sh` (берёт `builds/source_latest.zip` → `turbo-vendetta_latest.zip` в корне → `project/`);
   - если Pod «сплющен» (все файлы в корне, папок нет — так было дважды 2026-10-25): `bash /files/pod/restore_flat.sh`, затем сразу чекпоинт;
   - после перехода на GitHub: см. раздел «Источник истины».
6. Сверь версию в `project.godot` / `CHANGELOG.md` с последней записью лога. Расхождение = сначала разобраться.

## Ритуал чекпоинта
Требование продюсера (2026-10-25): **сохранять каждый шаг**. Сделал что-то — сохранил. Чекпоинт после каждого законченного куска работы (новый файл, правка документа, найденный факт), после каждого подэтапа, перед любой рискованной операцией. Не копить изменения «до конца подэтапа».
1. Запись в `docs/PROGRESS.md` (формат ниже) + обновить «ТЕКУЩУЮ ПОЗИЦИЮ» (`python3 tools/agent/progress.py docs/PROGRESS.md pos.md entry.md`). Мелкий шаг внутри подэтапа — запись с пометкой `WIP`.
2. `bash tools/agent/checkpoint.sh` — одна команда делает всё: метка `BuildInfo.STAMP` в `scenes/boot/build_info.gd` (видна пользователю в меню спайков и в «Выводе» — по ней ясно, какой архив он запустил) → `tools/validate.py` (если есть) → синхронизация `tools/agent/sync_dir.py` в `/files/pod/project/` (rsync в Computer нет) → архив `builds/source_latest.zip` → копия архива в корень Pod `turbo-vendetta_latest.zip` → снимок `builds/history/turbo-vendetta_ГГГГММДД-ЧЧММ.zip` (последние 15) → плоские копии `AGENTS.md` и `docs/*.md` в корень Pod → копия архива в файлы разговора → проверка архива и числа файлов. Без строки `checkpoint … ok` чекпоинт не считается.
   При закрытии версии дополнительно: `/files/pod/builds/releases/turbo-vendetta_vX.Y.Z_src.zip`.
3. Отметить чекбокс в `docs/PLAN.md` (если подэтап закрыт) — и снова `checkpoint.sh`.
4. Исходник любого артефакта (скрипт рендера, генератор, конфиг) лежит рядом с результатом (`src/`) — в этом же чекпоинте. Песочница временная: 2026-10-25 так потерялся рендерер кадров стиля.
5. Скачанное из сети (навыки, справка) — сразу в `/tmp/work` и сразу чекпоинт, до любой обработки.

**Нельзя заканчивать сессию без чекпоинта.** Если работа прерывается на середине подэтапа — чекпоинт с пометкой `WIP` и точным описанием, что сделано наполовину и что дальше.

## Жёсткие правила

### 1. Архитектура — композиция, не наследование
- Сущность = сцена `.tscn`: корневой узел движка + дочерние узлы-компоненты.
- Компонент: одна ответственность, `class_name XxxComponent`, наследуется **напрямую** от типа движка (`Node`, `Node3D`, `Area3D`, `RayCast3D`…). Своих базовых классов и цепочек наследования нет.
- Связи между компонентами: `@export var engine: EngineComponent`, назначаются в сцене. Никаких `get_node("../../X")` строками.
- Вверх — сигналы, вниз — вызовы методов. Глобальные события — автозагрузка `EventBus`.
- Данные — в `Resource` (`.tres`): `CarSpec`, `AbilitySpec`, `TrackSpec`, `LeagueSpec`, `BossSpec`, `TrackCondition`. В рантайме не мутируются.
- Управление машиной — сменный компонент с общим контрактом: `PlayerInput` / `BotInput` / `GhostPlayback`
  (свойства `throttle`, `brake`, `steer`, `drift`, сигналы `ability_attack_pressed`, `ability_defense_pressed`).
  Передача «призрак → бот» = замена активного источника управления.
  Контракт хранится в узле `CarControlsComponent`: активный источник пишет в него, остальные компоненты читают только его (D-014). Деревья сцен, порядок такта физики и белый список спауна — `docs/ARCHITECTURE.md`.

### 2. Никакой генерации объектов кодом
- Всё, что существует в игре, собрано в `.tscn` из узлов.
- **Запрещено:** `MeshInstance3D.new()`, `Node3D.new()` и любые узлы через `.new()`; `add_child()` самодельных узлов; процедурная геометрия в рантайме (`SurfaceTool`, `ArrayMesh` в игровом коде).
- **Разрешено:** `PackedScene.instantiate()` заранее собранных сцен (машины в слоты стартовой решётки, снаряды из пула), `create_tween()`, данные-ресурсы.
- Модели: офлайн-инструмент `tools/meshforge/` (Python → `.glb`), аналог скриптов Blender. Результат — статичный ассет, который размещается в сценах. D-005 принято.
- Трассы: `Path3D` + `CSGPolygon3D` (режим Path) в `.tscn`, декор — сцены-модули и `MultiMeshInstance3D`.
- `tools/validate.py` проверяет запреты автоматически.

### 3. Тексты
- Все тексты для игрока — только ключи в `localization/strings.csv` (`keys,ru,en,_status`, D-015). В сценах и коде — ключи.
- Русский текст проходит навык **humanizer-ru** (https://github.com/Vladimir-Human/humanizer-ru), английский — **humanizer** (https://github.com/blader/humanizer). Копии навыков — `docs/skills/humanizer-ru/` и `docs/skills/humanizer-en/`, порядок работы — `docs/TEXT_PIPELINE.md`.
- Статус строки: `draft` → `humanized`. Строка без `humanized` в релиз не идёт.
- То же для описаний в каталоге Яндекса и экранов обучения.

### 4. Шейдеры
- Папка `res://shaders/`. В шапке каждого файла: источник (URL), автор, лицензия, что изменено.
- godotshaders.com: только **CC0** и **MIT**. GPL v3 не берём (заразит лицензию игры).
- Shadertoy: по умолчанию **CC BY-NC-SA 3.0** (некоммерческая) → в игру с рекламой копировать нельзя. Берём только шейдеры, где автор явно указал MIT/CC0, иначе пишем свою реализацию по идее.
- Каждый шейдер обязан работать в Compatibility (WebGL 2). Все заимствования — в `CREDITS.md`.

### 5. Яндекс Игры
- Требования: https://yandex.ru/dev/games/doc/ru/concepts/requirements — сверяться при каждой фиче управления, UI, рекламы, сохранений.
- Всё общение с SDK — только через автозагрузку `YandexSDK` (с моком для редактора).
- Ключевое: управление одной рукой на мобильных, клавиши по `physical_keycode`, пауза звука при потере фокуса и рекламе, реклама только в паузах, награда за rewarded — только бонус, гостевой прогресс сохраняется, размер ≤ 100 МБ.

### 6. Качество
- Статическая типизация GDScript везде; `untyped_declaration` = ошибка.
- «Fancy & juicy»: у каждого значимого действия минимум 2 канала отклика (визуал + звук). Визуальный язык — `docs/STYLE_GUIDE.md` (§6 эффекты, §9 таблица «сока»).
- Любое число (тайминг, скорость, бюджет) = «стартовое значение + как проверить + куда крутить».
- Версии: SemVer `0.MINOR.PATCH`. Каждая закрытая версия — запись в `CHANGELOG.md`.

## Ограничения окружения (Computer)
- Нет Godot и Blender, сеть закрыта (allowlist пустой), пакеты ставить нельзя.
- Есть: Python 3.14, numpy, Pillow, opencv, scipy, ffmpeg, imagemagick, git, zip. 2 CPU, 1 ГБ RAM.
- `files__upload_from_url` не принимает zip → Godot так не скачать.
- `ls` в Computer — функция оболочки `ls -al` (наследуется скриптами): в скриптах списки файлов только через `find` или `command ls` (2026-10-25 17:02 из-за этого упала чистка `builds/history/`).
- Запуск в движке и веб-сборку делает пользователь по чек-листу из лога (D-004). В каждом чекпоинте — чек-лист: что открыть, что нажать, что должно получиться.
